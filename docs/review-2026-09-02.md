# Adversarial review — 2026-09-02 (pre-M2)

Scope: everything on `main` at e8b7068 (M1.1 + TTS), read end to end,
with the question "will this work the day the Pis arrive, and can a
rider or chase passenger use it without the author present?". Findings are
ordered by what would have bitten first. **Fixed** = landed in this session
with a test; **open** = noted, not done.

## A. Would have failed on real hardware (fixed)

| # | finding | evidence | fix / test |
|---|---|---|---|
| A1 | **Mixer and bridge downlink bound to 127.0.0.1.** No real bridge could reach the mixer or receive a downlink. | `PyMixer.start` / `BridgeEngine.start` hardcoded loopback | `bind_host` on both, base binds 0.0.0.0 by default (roster `net.mixer_bind` overrides). S-14, S-16 |
| A2 | **Ducking never worked off-box.** `BridgeAgent` never sent `vad`; the orchestrator's ladder only reacts to `vad` messages. The demo hid this by wiring `on_vad` in-process. | `bridge/agent.py` had no vad path; `sim/demo.py` passes `on_vad=orc.on_vad` | Engine fans gate state out to listeners; the agent forwards it as `vad` (and re-sends state on reconnect). S-15 asserts a bridge's gate ducks the mixer over a real socket |
| A3 | **Roster needed every bridge's IP.** Downlink address came from `rider.ip` (default 127.0.0.1). | `Orchestrator.populate` | Symmetric RTP: the mixer replies to the host an uplink arrives from; survives re-populate; `learn_peer=False` for tests that need fixed addresses. S-14 |
| A4 | **Mixer concealed forever after a >1.4 s gap mid-sentence.** The reorder buffer kept the newest 24 packets while `next_seq` advanced one per tick — permanently behind. Reproduced: 300 ticks after a 40-packet gap, 0 real frames decoded. | script in session; `pymixer._pop_frame` had no resync (the bridge's `DownlinkChain` did) | Resync to the oldest held packet after 3 consecutive PLC frames; `resyncs` in stats. S-14 |
| A5 | **Sequence wrap glitch** every ~65 min: `min(buf)` on raw 16-bit seqs picks 0 over 65535. | both reorder buffers | Serial arithmetic (`seq_ahead`, `oldest_seq`). S-14 wraps a downlink across 65535→0 with zero concealment |
| A6 | **No bridge entry point, no config, no real audio IO.** `BridgeEngine`/`BridgeAgent` existed but nothing ran on a Pi. | repo map: `tools/bridgectl` stub | `bridge/main.py` (+ `--sim`), `bridge/config.py` reading /boot/convoy.toml, `CmdSource`/`CmdSink` subprocess adapters with supervision, `deploy/*.service`. S-16 |
| A7 | **Eviction policy unwired; no link stats provider.** | catchup M2 item 4 | `bridge/net/linkstats.py` parses `iw station dump`; loss measured from concealed downlink frames; policy ticks in `bridge/main`. Missing data is treated as healthy (an eviction is itself an outage). S-16 |
| A8 | **`DeviceActions.reconnect_bt/wifi` fell through to the sim implementation** and would have acked "sim bt cycled" on a real bike. | class only overrode `reboot` | All device shells implemented, MAC-validated, `DRY-RUN:` until `[actions] enabled`. S-16 |

## B. Robustness (fixed)

| # | finding | fix / test |
|---|---|---|
| B1 | One malformed UI message (e.g. `move` with an unknown pid) raised inside the WS handler and closed that client's socket with 1011. Reproduced. | Every message path validated; handler catches and logs; unknown riders ignored. S-15 sends 12 kinds of junk then proves the socket still works |
| B2 | Dashboards polled `hello` every 2 s; `_ui_clients` was collected but never used. Talking badges under 2 s were invisible; every click needed a second round-trip. | Snapshots pushed on change (80 ms debounce) and at 1 Hz; pages keep a 10 s keepalive. S-15 |
| B3 | Any WS client could `hello` as a node and hijack its command channel. | Optional `net.node_token` (roster) / `[net] node_token` (toml); unknown ids rejected. S-15. UI stays unauthenticated by design (documented) |
| B4 | Heartbeats from unknown ids polluted `node_status`; `on_gps` crashed on non-numeric input; `trim` accepted strings. | Guarded. S-15 |
| B5 | Static server: no content types beyond html, query strings 404'd, prefix-based traversal check. | Route table, `commonpath` check, `/snapshot.json` + `/health` for curl diagnostics. S-17 |
| B6 | Heartbeat task exceptions after a drop were unobserved ("Task exception was never retrieved"). | Sends wrapped; agent logs link up/down transitions once |
| B7 | `on_vad` used `asyncio.get_event_loop()` (deprecated without a running loop). | `get_running_loop()` with a synchronous fallback |
| B8 | Earcons: `SimActions._earcon` ignored the name and beeped 990 Hz for everything, so SAFE-2's "audible truth" was one indistinguishable tick. | Uses `common.earcons.render`; new specs `identify`, `volume`, `ptt_on/off`. S-16 checks they are audible at 10 % volume |

## C. Usability (fixed)

- No page for riders; the ops dashboard was `/` and assumed the operator.
  Now `/` is a two-button landing, `/rider` is the phone page (big PTT,
  volume, room, headset pairing, link word, messages, acks as toasts,
  remembers who you are, PWA manifest, wake lock), `/ops` the dashboard.
- Nothing printed the LAN URL. `make up*` prints every address + QR.
- No way to make a virtual rider speak on demand: `say` node command, and
  the sim runs forever (`make up-sim`) instead of 40 s.
- Rider ids were injected into inline JS strings unescaped; now data
  attributes + escaping everywhere.
- Ops page shows peer IP, PTT, VAD mode (red when demoted), headset state,
  sim speed slider, pending/ok/failed acks in a log.
- **PTT** closes the DR-008 gap operationally: at 120 km/h the gate misses
  ~20 % of speech; the rider's thumb now forces it open (bypass, not a
  threshold change — the profiles table is untouched).

## D. Test quality — what was missing, what still is

Was missing, now covered (23 new tests, 34 → 57): wrap arithmetic, mixer
resync, peer learning, WS junk, push cadence, off-box ducking, PTT,
pairing round-trip, token gating, iw parsing, loss window, TOML config,
subprocess adapters (dead mic → silence, never `None`), dry-run guard,
earcon audibility after volume, HTTP routes/traversal/JSON, no-CDN pages.

Still open:
- **O1** Realtime tests share fixed ports; `pytest -n` would collide. Low.
- **O2** S-05 asserts <350 ms one-way in sim; no test pins the mixer's
  tick jitter under load (H-03 territory; needs hardware).
- **O3** Gate metrics (S-03/S-04) take ~45 s of the 60 s suite; fine, but
  there is no `make test-fast` path that still exercises the gate on one
  tier. Consider `-k "50"` marker.
- **O4** No test drives the HTML with a browser. Playwright is installed
  here and was used manually (screenshots in the session); a headless
  smoke (open `/rider`, pick, hold PTT, expect `ptt` in snapshot) is
  ~30 lines and would catch JS regressions. Recommended before M2 ends.
- **O5** `DeviceActions` shells are tested via injected fake commands; the
  real bluetoothctl/wpa_cli invocations are unverified until hardware.

## E. Substantial improvements worth doing next (not done)

1. **Bridge-local rider page.** Serve `rider.html` from the Pi too (same
   file, WS target = itself) so pairing works with the base down. DR-010
   revisit condition.
2. **RTCP-lite.** Bridges could report downlink loss per second in
   heartbeats already; the mixer could use it to raise Opus expected-loss
   (`OPUS_SET_PACKET_LOSS_PERC`) per listener dynamically. Cheap win for
   the straggler.
3. **Per-command timeouts in the orchestrator** (DR-009 revisit): a
   `pending` ack older than 10 s should flip to failed so the phone page
   never spins forever on a dead node.
4. **GPS.** `on_gps` exists; nothing feeds it. The chase phone's browser
   Geolocation API can post `gps` from `/ops` (one `watchPosition`).
5. **Roster hot-reload** (SIGHUP) so adding a rider does not restart the
   mixer mid-ride.
6. **CPU on the 3A+**: DR-001's revisit condition (>30 % of a core) is
   untested. `bridge.main --verbose` should print the tick's busy fraction;
   `prefer_silero=false` in the toml is the fallback, and SAFE-1 will
   demote automatically if it is too slow (observed in sim here with 5
   Silero instances in one process).
7. **`make demo` still wires `on_vad` in-process**; it now also gets the
   agent path, so `duck` events fire twice (harmless, idempotent). Clean
   up when the demo is next touched.

## F. Second pass on the PR itself (same day)

Re-read the diff adversarially before merge. Real defects found and fixed,
each with a test in S-16:

| # | finding | fix |
|---|---|---|
| F1 | **PTT could stick open.** If the control link dropped while the thumb was down, the release never reached the bridge and the gate stayed forced open (wind on the air) until the link returned. | PTT is a dead-man switch: the page re-arms every 2 s, the engine releases 6 s after the last arm with the ptt-off earcon, and the page sends an explicit off on every reconnect. |
| F2 | **`iw station dump` ran synchronously inside the async loop** every second, so a hung `iw` (up to its 1.5 s timeout) would stall the 60 ms audio tick. | Runs in a worker thread; the caller gets the previous reading. |
| F3 | **Enabled `reboot` never rebooted.** The enabled branch returned "rebooting" without running the shell. | Fires the shell without awaiting it (the box goes away). |
| F4 | **Loss window split between two callers.** Heartbeat and the eviction tick both cut the window, each seeing half the loss. | Window re-cut at most once per second; both get the same number. |
| F5 | **Rider page rebuilt its buttons on every 1 Hz snapshot**, so a gloved tap could land on a node that had just been replaced. Verified with 8 rapid taps under streaming pushes after the fix. | Blocks re-render only when their markup changes. |
| F6 | A dead audio command was restarted every second with earcons each time. | Restart at most every 5 s. |
| F7 | `deploy/roster.example.yaml` used `mixer_ip` where the code reads `net.mixer_bind`. | Key fixed. |

Left alone on purpose (reasonable, not wrong): UI clients stay
unauthenticated (LAN trust model, documented); `tts.engine_name()` does
two PATH lookups per pushed snapshot (negligible); the demo still wires
`on_vad` in-process alongside the agent path (idempotent).
